# 面试演示脚本

本 Demo 聚焦本人负责的对话分流、打样参数补齐、BOM 合并和异常标记。建议按下面顺序演示，约 2–3 分钟。

## 开场说明（约 15 秒）

“整体项目把资料、物料、BOM 和下单串联起来。我负责的是入口的对话调度与需求补齐，以及出口的 BOM 合并和异常标记。这个仓库是我围绕这两部分独立复现的展示 Demo，中间环节使用构造 BOM 作为输入。”

## 入口：对话分流与参数补齐

1. 展开“对话设置”，选择 DeepSeek 自然对话；没有 API Key 时选择离线规则演示。两种模式都支持下列明确格式。
2. 点击“试试缺项追问”填入 `4层，100x80mm，先做10块`，再点击发送。
3. 指出“报参数”的分流结果。确认卡片前，右侧原值保持不变；点击“确认更新”。
4. 右侧仅剩工艺和交期缺失，助手先追问工艺。发送 `沉金，7天` 并确认，展示五项齐全。
5. 发送 `改成20块，其他不变`，确认前后对比数量 10 → 20，强调其他字段保持原值。
6. 发送 `改成30块`，选择“暂不修改”，展示数量仍为 20。
7. 展开“更多场景”，点击“问参数”“问替代料”“要出单”展示不同去向。点击“不确定意图”展示反问和四类快捷确认入口。

讲解重点：模型负责理解，程序维护已确认字段和缺项；避免重复问已知内容，也避免把咨询当成正式修改。

## 出口：BOM 合并与异常标记

1. 进入“BOM 校验”页，加载“同键合并示例”，确认替换 BOM；对话和打样参数仍保留。
2. 对照原始与合并表：第 1、2 行同型号同封装合为数量 3，来源可追溯；第 3 行同型号但 0805 封装单独保留。
3. 指出数量 6 / 6、位号条目 6 / 6。强调合并前后核对避免漏料。
4. 加载“异常检查示例”。展示重复位号关联两行、型号封装冲突、缺失数量。点击异常，定位到对应行和字段。
5. 请求出单或查看导出按钮，展示异常未消除前拦截。
6. 点击“应用示例修复”，或手动把第 2 行位号改为 `R4`、第 3 行封装改为 `0603`、第 4 行数量填为 `1`。
7. 规则通过后导出 CSV。20 块板下，合并后的 3 个单板电阻总需求为 60 个；两种模板仅改变字段顺序。

讲解重点：不同封装不混合，重复位号不静默去重；异常数据保留在预览中，但不进入可导出的需求单。

## 收尾边界

- 图纸识别、选型和规格书检索不是本人在该项目中负责的模块，不作为个人独立实现成果。
- DeepSeek 是当前 Demo 的自然语言适配；辅助问答、人工交接和 CSV 导出用来展示流程，不代表完整客服产品。
- 型号封装仅有标注清楚的示例规则，厂商模板也仅为展示格式。
- 演示数据为构造数据，不含原实习单位资料，不虚构生产规模或准确率。
