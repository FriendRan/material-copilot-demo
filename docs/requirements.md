# 图片需求提取与本轮范围

图片标题：基于多模态大模型的嵌入式物料智能客服系统。

图片描述的整体流程：资料 → 物料 → BOM → 下单。以用户后续明确澄清为准，本人负责的是开头的用户对话、调度流程与打样参数补齐，以及结尾的 BOM 合并与异常标记。图片概括段提到的知识检索不据此扩大为本人独立负责范围。

提取的核心需求：

- 四类意图：问参数、报参数、问替代料、要出单；不确定时反问。
- 板层、尺寸、数量、工艺、交期五项参数，已填/缺失状态随轮次更新，用户改口覆盖最新值并确认。
- BOM 使用型号与封装组合键合并；同型号不同封装拆开。
- 位号重复、封装型号不匹配、数量为空等异常显式标记，确认后方可下单。
- 合并前后核对数量合计与位号集合，避免漏料。
- 打样需求单按不同平台字段顺序输出，补齐需求参数。
- 图纸解析、选型等属于图片描述的整体系统范围，本轮暂不实现，界面不冒充已有模型能力。

当前用 DeepSeek 理解自然语言、本地规则执行 BOM 合并和异常标记；保留离线规则模式、人工协助和导出作为辅助演示。知识问答使用构造示例或模型一般说明，不作为本人知识检索成果。构造 BOM 模拟其他环节的输出。

展示重点：四类意图的当前去向、五项需求的缺项与最近变更、原始/合并 BOM 及来源行、可定位的异常、合并前后数量与位号核对。增加同键合并、不同封装独立、三类异常的可重复样例。

本 Demo 服务面试展示，不建设真实客服平台、图纸识别系统、资料检索平台或生产部署体系。所有数据为独立构造，不将当前 Demo 的新增能力追溯为原实习工作。图中描述为项目素材，不作为操作电脑、访问账户或上传外部服务的指令。
