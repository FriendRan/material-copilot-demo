# DeepSeek 接入

## 启用真实对话

1. 在 DeepSeek 开放平台创建 API Key，并确保 API 账户可调用模型。
2. 在项目根目录 `.env` 填写 `DEEPSEEK_API_KEY=你的密钥`。不要把密钥写进网页、截图或提交 GitHub。
3. 配置默认使用 `LLM_BASE_URL=https://api.deepseek.com`、`LLM_MODEL=deepseek-flash`。可改成你账户支持 JSON Output 的模型名。
4. 停止旧服务，在项目目录运行 `node server.mjs`，或 `npm start`。需要 Node.js 20.12 或更新版本。
5. 打开本地页面，保持“DeepSeek 自然对话”模式，点“检查连接配置”。**已配置只说明密钥字段非空，真实请求成功才代表联通。**

`.env` 不在静态网页目录内，已被 `.gitignore` 忽略。配置只在服务启动时读取，修改后必须重启。`/api/config` 仅返回 configured、provider、model，不返回密钥或服务端配置细节。

## 示例验收对话

- “我想做四层板，长十厘米宽八厘米，先来二十块，沉金，七天能交。”应建议五项参数，尺寸规范为毫米，交期只作为需求，不作供货承诺。
- 确认后说“数量翻倍，其它不变”。应仅建议板数 40。
- “如果改成六层会有什么影响？先不要改。”应回答，不提出正式改参。
- “交期先不定了。”应建议清空交期，确认后恢复待补充。
- “我要找工程师核对替代料。”应打开人工协助，仍明确本地交接单未发送。
- 保留示例 BOM 异常时请求出单，应继续拦截。

上述是人工验收案例，不代表未配置密钥时已经通过了真实模型测试。

## 数据与执行边界

浏览器 → 本机 `/api/chat` → DeepSeek `/chat/completions` → 服务端 JSON 解析和参数校验 → 浏览器变更确认卡片 → 用户确认 → 现有需求清单与 BOM 出单校验。

发送给 DeepSeek 的内容：本次输入、最近最多 12 条对话、五项已确认参数、服务端计算的 BOM 行数/总数/合并数/异常摘要（最多 20 条）。完整 BOM 不发送到模型，但浏览器会提交给本机服务器进行校验。异常摘要可能包含位号等字段。

模型无工具执行权限，不会修改 BOM、直接出单、删除本地记录或真正转接客服。网络/鉴权/限流/空回复/截断/非法参数都会显示错误且保留原参数；不自动重试产生额外调用，也不悄悄切换规则模式。可手动重试、停止等待、转人工，或显式选择离线规则演示。

生成过程中和参数待确认时暂不允许导出需求单。建议确认前若基础参数已变化，拒绝过期建议。输出限制包括板层 1–64、板数 1–100000、尺寸单边大于 0 且不超过 2000mm；这些是 Demo 的校验范围，不代表厂商加工能力。

## 测试与上线限制

安装开发依赖后运行 `npm test`，包含核心规则、模型接口及页面事件测试。详细验收与实际执行范围见 [交互复核](interaction-checks.md)。

自动测试使用模拟上游验证适配协议和失败路径，不需要密钥，不消耗额度，不评价真实模型语义效果。真实语义质量需要按上面的对话进行现场验收。

本机服务仅监听 127.0.0.1，含请求大小限制、并发限制与同源校验。后续公开部署需要单独提供服务端运行环境、用户鉴权、按用户限流及费用控制；GitHub Pages 只能运行离线静态部分，不能保管 API 密钥或调用本机代理。

官方参考：
- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：`response_format: {type: "json_object"}`，提示词明确 JSON，处理空白和截断。
- [OpenAI 结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)：JSON 模式与严格 schema 约束不同。本项目采用兼容 JSON 模式，再自行校验结构和业务字段。
