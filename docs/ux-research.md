# 智能客服交互调研与 V0.2 改进

查阅日期：2026-11-20。以下为官方文档调研，不代表已接入相应厂商服务。

## 参考

- [Intercom：Fin escalation guidance and rules](https://www.intercom.com/help/en/articles/12396892-manage-fin-ai-agent-s-escalation-guidance-and-rules)：明确请求人工、用户挫败或重复对话是升级处理场景；直接转交与建议升级是不同动作。Fin 的文字对话主要通过自然语言转交，因此本 Demo 的常驻按钮是结合用户要求做出的设计选择，并非照搬其界面。
- [Zendesk：AI agent conversation statuses](https://support.zendesk.com/hc/en-us/articles/8854858307610-What-are-the-conversation-statuses-for-AI-agents)：区分 AI 协助升级、实际转接成功和转接失败。Demo 因未连接客服服务，只显示本地草稿状态。

## 本轮落地

| 场景 | 行为 |
| --- | --- |
| 随时需要人工 | 顶部常驻入口，Alt+Shift+H；输入“转人工”直接打开面板 |
| 连续两次未理解 | 展示人工协助建议，也允许继续自助；阈值为本 Demo 自定规则 |
| 知识库无答案 | 显式建议人工核对，不生成无依据答案 |
| 替代料查询 | 给出核对清单，并提供工程师协助入口 |
| 回答未解决 | 单条回答反馈按钮，记录反馈并展示升级入口 |
| BOM 异常 | 在 BOM 区域提供工程师核对入口 |
| 交接 | 可编辑原因与补充说明，保存五项参数、BOM、异常、最近最多 100 条对话 |
| 状态 | 未创建 → 本地交接单已保存 → 继续自助；没有虚构在线客服或等待时长 |

交接单保存后为独立快照，支持手动更新与 JSON 下载；当前保留最近一份交接单。选择继续自助会标记该单为本地结束，内容仍保留。所有状态在当前浏览器保存。澄清按钮也随状态重新渲染，刷新不会丢失待澄清入口。

## 后续真实接入

需要服务端工单 API、人工坐席工作台、队列与营业时间、接单回执及消息通道。只有后台确认转接成功才能显示“已接入人工”；真实坐席接管后才暂停自动回复。目前不会发送任何消息到外部服务。
